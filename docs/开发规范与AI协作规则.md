# 开发规范与 AI 协作规则（精简版）

适用于本项目开发者及其 AI 助手。本项目基于 ruoyi-vue-pro / yudao-vue-pro 二次开发，业务边界与跨模块契约见[文档导航](./README.md)。每次任务都向 AI 提供本规范、任务范围及验收要求。

## 1. 修改范围

- 开发前确认成员身份、任务、项目路径和允许修改的文件，先阅读现有实现；不明确时先询问，不自行扩大权限。
- 只修改本人模块中与任务有关的页面、接口、数据操作、测试和文档。不重构、删除或覆盖其他成员代码及未提交修改。
- 修改其他模块、公共组件、全局路由、认证、依赖或环境配置前，由对应负责人或集成负责人确认具体变化。已有明确授权无需重复确认。
- 源资料用于阅读，成果写入 yudao 业务项目；实际目录以工程为准，不猜测路径。

## 2. 数据库与环境

- 每人使用独立开发库、本地后端和 Redis；共享联调环境由集成负责人维护，未经授权不得改表、清库或重启服务。
- 表结构变更提交增量 SQL，说明原因、执行顺序和验证结果；先在个人库验证，再由负责人同步共享库。已执行的迁移不改写，修正另建脚本。
- 不直接修改其他模块负责的表；库存、支付、积分通过对应服务操作，不重复实现写入逻辑。
- 执行 SQL 或测试前确认目标环境。密码、密钥、个人配置和真实会员数据不得提交 Git 或发给 AI。

## 3. 代码与接口

- 遵循 yudao 现有技术栈、目录和代码风格，优先复用已有功能。不擅自新增框架、升级依赖或开发任务外功能。
- 药店业务代码位于 `backend/yudao-module-pharmacy`；管理端页面位于 `admin-ui/src/views/pharmacy`；管理端接口位于 `admin-ui/src/api/pharmacy`；小程序位于 `mall-uniapp`。药店业务表使用 `ph_` 前缀，框架表沿用现有结构。
- 不为登录、权限、菜单、字典、会员账号、支付基础结构重复建模块或重复建表；优先复用 `system`、`infra`、`member`、`pay`。
- 跨模块接口先约定参数、返回值、状态、金额单位和失败处理，不擅自改变已被使用的接口。
- 后端校验输入、权限、数据归属和业务状态，不能只依赖前端按钮控制。
- 基础资料维护覆盖门店、员工、分类、药品与条码；员工关联框架账号，药品条码唯一，被业务引用的主数据删除前必须校验。药品/条码查询契约明确 ID、分类、名称、规格、条码、价格、处方属性及启用状态，供销售等调用方拦截停售药品。
- 金额精确计算，统一元与分转换；库存变更与流水保持事务一致，收货、销售、退款等操作防止重复执行。
- 不通过关闭校验、吞掉异常、硬编码成功或伪造数据解决问题。Mock 必须明确标识，不能当成真实联调成果。

## 4. Git 与验证

- 使用个人功能分支和独立工作目录，及时同步主分支；不直接推送主分支，不强制覆盖别人的工作。
- 提交前检查差异，只保留任务相关文件；公共变更和数据库脚本随合并申请说明。提交不包含 `.env`、密码/密钥、真实业务数据、`node_modules`、`target`、日志和无关 IDE 配置；冲突处理不得覆盖他人改动或强制推送。
- 按改动验证正常流程、错误输入和权限；交易类还需验证重复提交、库存不足及失败回滚。
- AI 未获得当前任务明确授权时，不自动推送、部署或操作共享环境。
- 完成后说明修改文件、实际验证结果、数据库变更和剩余问题；未运行的检查如实说明。

## 发给 AI 的任务模板

```text
请阅读并遵守本规范及我的分工。
成员编号：
负责模块与表：
业务项目路径：
yudao 二开位置：
本次任务：
允许修改的实际文件或目录：
依赖的其他模块接口：
验收标准：

先检查现有代码并给出简短计划，再完成范围内开发和验证。
需要跨模块或公共修改时，说明原因及文件，等待负责人确认；
继续完成不受影响的工作。不得擅自修改共享环境。
最终列出修改文件、验证结果、迁移要求及未完成项。
```

本规范是协作约定，不会自动配置 Git 或数据库权限；须将规范和已填写的任务信息提供给 AI。

## 本地开发环境与依赖

| 组件 | 开发约定 |
| --- | --- |
| Java / Maven | JDK 17、Maven 3.9.x；`java -version` 与 `mvn -version` 均核对实际 JDK |
| Spring Boot | 3.5.15；版本以仓库 POM 为准，不引入仅支持 Java 8 / Spring Boot 2 的代码 |
| 管理端 Node / pnpm | Node 22.x、pnpm 11.22.0；最低版本与依赖以 `admin-ui/package.json` 和现有锁文件为准 |
| 数据与缓存 | MySQL 8.x、Redis 7.x |

管理端使用 pnpm 和 `pnpm-lock.yaml`，不要混用 npm 生成管理端 `package-lock.json`；依赖变更配套更新其清单与锁文件。小程序沿用自身 npm 清单与锁文件，构建见[小程序部署说明](../mall-uniapp/README.deploy.md)。安装路径可不同，不把本机 JAVA_HOME 或个人绝对路径写入项目文件。

本地根 Compose 的默认入口为管理端 `http://localhost`、后端 `http://localhost:48080`、MySQL `127.0.0.1:3307`、Redis `127.0.0.1:6379`，数据库默认 `firstsun_pharmacy`；实际值以个人配置为准。根 `.env` 不纳入版本管理。交付 Compose 的端口与隔离方式另见[部署指南](../deploy/README-deploy.md)，不要把本地端口约定套用于交付环境。

增量迁移顺序见[迁移说明](../sql/migrations/README.md)。重建数据卷会丢失原数据，不能用清卷代替已有库升级；先确认目标环境及保留数据要求。提交/审查说明应写明改动范围、验证方式和迁移要求，生成 CRUD 或构建成功不等于真实业务联调通过。

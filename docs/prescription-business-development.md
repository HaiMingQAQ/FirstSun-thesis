# 处方购药与业务通知开发记录

## 复用、适配与新增

- 直接复用：会员令牌与租户过滤、药品档案、门店员工及执业资质、处方登记／审核／作废服务、购物车与会员订单、实际库存扣减、积分释放、系统通知表与已读接口。
- 适配：顾客提交使用私有材料 ID；药师核准固定药品、数量、用法用量及有效截止时间；下单与支付独立校验；取消与超时在既有订单事务内释放未支付使用记录。
- 新增缺口：私有图片存储与鉴权下载、提交摘要与请求编号去重、单笔使用记录、顾客通知接口及页面、后台材料预览与结构化核准表单、订单自动超时任务。没有新增 Redis 用途或外部服务。

私有图片仅接受经过解码校验的 PNG/JPEG，1–3 张、单张最多 5MB。存入独立私有表，通用文件 URL 无法寻址；本人或具有处方查询权限且属于本门店、在职、执业资质有效的药师才能读取图片。响应不缓存，不接受 SVG、网页或外部 URL。通知只存状态提示及关联处方 ID，不放患者信息或图片。

## 服务端约束

顾客不能审核自己。药师只能核准原申请药品的子集，数量不得增加，须填写用法用量与未来截止时间。商品名称及规格重新取数据库档案，特管及含麻黄碱商品不进入本在线流程。

结算只能使用全部核准明细和数量，不得混入其他商品。租户、会员、门店、处方状态、有效期、商品状态、实际库存、活跃使用记录均由服务端校验。支付还会重查实际订单行与核准快照，前端隐藏按钮不是授权。`HELD/PAID` 使用记录有租户范围的活跃唯一键。

按用户确认：未支付取消或超时后自动恢复；新订单仍需通过上述校验。已支付使用不因退款自动恢复。超时任务无登录用户，使用记录审计更新者明确为 `SYSTEM`，不伪造员工身份。

历史公开材料或没有结构化核准明细／有效期的处方不自动取得新购买资格。驳回后可修改材料并提交新的待审申请，不自动转为通过。

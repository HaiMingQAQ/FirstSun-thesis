# 症状问药检索修复（2026-10-03）

## 原因与实现

此前商品浏览可通过分类返回商品，但症状问药依赖模型给出的单个原文关键词，并过滤掉全部无货商品。本机已有感冒灵颗粒／胶囊的说明摘要（包含鼻塞、流涕），当前库存为零，因此原流程显示“没有匹配”。

- 在既有顾客 AI 服务中增加有限的同义表达：流鼻涕／流涕、打喷嚏／喷嚏、头疼／头痛、发烧／发热、嗓子疼／咽痛，以及鼻塞、咳嗽、感冒。不根据症状推断疾病；直接否认的症状不进入同义词集合。
- 当模型返回普通聊天或改写症状时，仍可按会员明确提供的症状检索；有限历史只读取用户消息，不使用模型历史回答创造检索依据。原写操作、危险症状、身份、租户和门店门禁保持。
- 对说明进行关键词初筛，再核对标明“适应症／功能主治／适用范围”的正文。不以药品名称、分类、禁忌或备注中的词语证明适用性；缺少这类资料的商品不作为症状候选。
- 复用原审核、线上销售、非处方及非特殊药品筛选，价格和库存继续读取服务端。问药资料允许展示零库存商品，优先有货商品；分类浏览仍仅展示可售库存商品。
- 服务端明确输出相关非处方资料名称及全无货提示，真实模型基于已核对资料解释条件性的用途参考。不能把部分症状匹配等同于确诊或个人适用性；不输出个体剂量，不代下单。
- 模型回复失败时保留已经核对的商品卡，状态仍为 `FAILED` 并明确提示重试，不伪造生成成功。失败日志仅记录阶段、异常类别及有限的安全原因枚举，不记录供应商异常原文。
- 复用原商品卡和详情页：显示“暂时缺货”，详情加购／购买仍受原库存校验。没有修改前端业务代码、药品数据、SQL、凭据或云端配置。

## 验证与范围

后端五组定向测试共 **34 项通过**，覆盖同义表达、明确否认、不引入疾病推断、意图格式错误时复用明确症状、仅禁忌命中排除、无资料排除、零库存保留／有货优先、服务端无货提示，以及原重复请求、越权、输出安全和历史删除。前端既有适配器定向测试通过。使用本机缓存依赖离线完成测试及打包；按既有运行镜像配置更新本套本地镜像，经 `start-local.bat` 启动。

真实模型及界面联调结果、截图存放于被 Git 忽略的 `.local/ai-symptom-real-20261003`，与单元测试分开记录。测试令牌及本地凭据不进入交付文件。

最终真实联调通过：独立测试会员输入“流鼻涕，打喷嚏，鼻塞”，返回感冒灵颗粒／胶囊两张资料卡，明确零库存；补充“成人，一天，没有发烧，没有过敏，没有其他用药”后仍匹配两项资料。进入商品详情，实际确认购买按钮禁用。浏览器无脚本错误。本机四服务健康，43 条迁移仍全部跳过。

本次续聊出现一次模型 `EMPTY_ANSWER`：已核对的两张药品卡没有丢失，前端显示回复失败并提供重试，重试后真实模型完成回答。该失败与恢复均计入验收；不能宣称模型调用每次都成功。供应商生成稳定性仍是剩余风险，不把空回复包装成成功。

本轮是有限词组和结构化摘要检索，不是完整医学语义检索或个体诊疗系统。未覆盖的表达、没有可靠说明摘要的商品仍需补充资料或人工核对。候选最多 20 条，初筛最多 61 条；截断时提示缩小范围。说明命中部分症状不证明用户一定适合使用该药。

已有历史回复按原幂等规则保留，不自动改写；验收须新建话题或发送新的消息。微信开发者工具运行和真机本轮未验证；本轮未暂存、提交或推送。

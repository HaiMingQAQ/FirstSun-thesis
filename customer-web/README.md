# FirstSun 电脑端顾客网站 · 接入第一、二批

独立 Vue 页面，保留 `FirstSun-web-prototype` 的购药主页、AI 工作区和商品详情视觉。基于主仓库 `4fa6d528403c6a30dc4d11f532ac6049a0f9b5cd`，两批均不需要后端源码或迁移改动。

## 本批可用

- 商品分类、名称搜索、分页、门店可售库存、真实商品 ID 详情。
- 顾客 AI 话题创建、历史列表/分页、历史重载、真实 POST SSE、错误重试、停止接收。
- 会员资料和退出；默认提供邮箱独立注册、邮箱验证码登录和邮箱密码登录，手机号不必填写。原手机号入口仍仅用于明确的本机验收模式。

第二批增加普通非处方药购物车、到店自提/本人已有地址配送结算、真实创建订单、订单分页/详情、待付取消和配送确认收货。只处理当前门店的实际购物车行 ID；金额与状态取服务端，usePoints 固定为 0。处方、人工咨询和真实支付仍明确未接入；不会运行静态原型中的合成成功逻辑。Rx 包装、说明书和材料不加载。缺图明确显示资料未提供，后端的演示占位图也不冒充真实包装。

## 复用

直接 import `../mall-uniapp/sheep/api/pharmacy/server.js` 及其 API 包装器、`common.js`、`sse.js`，不复制 AI 检索、模型策略、会员或订单规则。Vite 将其 `@/sheep/request` 和 `@/sheep/config` 指向 `src/request.js` / `src/config.js`；`src/session.js` 提供本批用到的 uni 存储接口，保留现有 token、refresh-token、firstsun-session 键和后端令牌契约。登录提交与启动资料恢复同时检查操作归属及组件生命周期，当前身份快照和代次用于拦截换号后的迟到响应；私有对话仅在 Vue 内存及服务端保存。

AI 页的流状态、请求标识、有限上下文、FAILED 新标识重试、断网原标识重试、历史恢复与商品卡映射适配自现有 `pages/pharmacy/ai.vue`。SSE 直接使用其 H5 fetch 路径，遵守 done/error 事件，不在浏览器调用模型或保存模型密钥。停止仅表示取消前端接收，不保证上游处理或计费停止；可稍后重载服务端历史。真实停止测试只观察了2500ms内可见文本未变化，没有证明真实迟到delta到达，也不证明任意晚到均受阻。

`src/prototype.css` 复制自独立静态原型以保留视觉，`src/live.css` 只补真实状态与布局修正。Lucide 0.468.0 及 ISC 许可证来自原型本地素材。

主要会员调用由共享server适配器设置 `skipRefresh:true`，本批登录过期后重新登录；没有宣称会员自动续期。历史刷新/失败重试读取最新一页，只有明确的“更早话题”操作会追加旧页。

## 开发和构建

Node 依赖由 package-lock.json 锁定：

```powershell
npm ci
npm test
npm run build
npm run dev
```

默认构建包含邮箱登录和注册表单，没有本机手机号测试表单或固定验证码。邮箱服务由后端独立开关和私有运行配置控制；未启用或配置缺失时显示后端不可用错误，不回退为开发验证码。发布时由同源 `/app-api` 接入后端；本轮没有切换运行服务或配置远程部署。

## 邮箱账号

注册先明确发送注册验证码，再提交邮箱、验证码和选填密码；已有邮箱使用登录验证码或密码登录，登录不会自动注册。地址去除首尾空白并转小写，接受最长254字符的ASCII邮箱，不合并供应商点号或加号别名。新设密码为8–64字符、UTF-8不超过72字节且不能全为空白；密码登录保留历史非空密码兼容。不填写密码可继续使用邮箱验证码，在个人中心凭本人已验证登录邮箱首次设密。

邮箱发送和消费分离，验证码只进入 `X-Email-Code` 请求头；提交不会隐式重发。注册、登录和首次设密用途独立。表单更换邮箱、切换模式或关闭时清除验证码与发送状态，迟到响应不能给新账号安装令牌、更新缓存或发出登录成功事件。表单不保存邮箱验证码或密码，沿用现有令牌与会员资料会话键。

`profile.loginEmail` 是后端返回的已验证登录身份，个人中心只读展示；`profile.email` 仍是可选、未验证的联系邮箱，编辑或清空不会改变登录身份。旧联系邮箱不会自动成为登录邮箱。邮箱注册不传手机号，后端使用 NULL；无手机号会员仍可读取资料、上传头像和使用现有会员业务。不提供找回密码、改绑、账号合并或真实短信。

接口为 `/member/auth/send-email-code`（JSON `{email,scene:"register"|"login"}`）、`email-register`、`email-login`、`email-password-login`、`send-email-first-password-code` 和 `email-first-password`。首次设密两接口只根据当前登录会员确定邮箱，不接受前端目标地址。可编辑资料PUT不携带 `loginEmail`。

本轮只用Node内存假fetch、组件脚本/模板离线编译和静态构建验证；没有真实邮件、认证或业务HTTP、数据库、模型、浏览器/UI证据。运行前仍需按新工作区任务说明准备后端配置和邮箱身份迁移。

## 独立本机验收

先确认后端是已授权的隔离回环环境。创建被忽略的 `.env.local-acceptance.local`，示例键见 `.env.local-acceptance.example`。随后：

```powershell
npm run dev:acceptance
```

地址 `http://127.0.0.1:4190/#catalog`，AI `http://127.0.0.1:4190/#ai`。测试入口要求 mode=local-acceptance、显式开关、HTTP 回环后端和浏览器回环地址同时成立，验证码由人工输入并走后端 send-sms-code / login-or-register 校验；没有默认验证码或预置令牌。该模式不代表正式顾客网页登录或微信登录通过。

配置只有后端地址、租户 ID 和开启标识，不含账号、验证码、令牌或模型密钥。切勿把验收模式构建当作发布版本。

## 第二批交易边界与验收

购物车/结算金额明确标为估算，创建后显示服务端最终应付；不在浏览器计算优惠或运费规则。处方药不能走普通结算，不提供地址新增/编辑、积分使用、退款或顾客自提核销。未知价格显示资料缺失，不冒充零元。

创建请求只发一次；发送后超时、连接失败、无法识别返回编号或服务 500 均视为结果未确定，阻止本次会话再次提交/重新进入结算，提示先核对订单列表。它不是后端幂等键实现；手工刷新会重建前端内存，不能据此承诺跨刷新创建幂等。

模拟支付要求 local-acceptance 模式、HTTP 回环页面和既有后端能力探测严格返回 true；每次支付前重新探测，失败默认关闭。它只用于已授权的隔离本机环境，不能作为真实支付。正式构建不含本机手机号测试登录表单或固定验证码；邮箱认证按上节接入。

购物车、地址、订单请求使用现有会员令牌/租户，过期后清理私有状态并重新登录，不自动刷新令牌或重发创建。组件按共享适配器实际返回的 userId 重建，防止刷新或切换账号后复用旧视图。定向异步测试与真实 HTTP/数据库证据分别记录，不把受控延迟当真实网络并发。

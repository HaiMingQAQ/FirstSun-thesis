# 电脑顾客端基础版整合

日期：2026-10-30。工作分支 `cursor/customer-web-mvp-a041`，从 `main`（`bbf7d3e0`）合并门店文字咨询（PR #4，`cursor/desktop-consultation-c770`）和处方申请（PR #5，`cursor/desktop-prescription-apply-2564`）后再修衔接。未合并到 `main`，未部署。

## 缺口与处理

| 缺口 | 处理 |
| --- | --- |
| 两个功能分支都改 `App.vue`，各自把对方入口留在「未接入」 | 同一壳层保留 `#consult` 与 `#prescriptions` / `#rx-submit` / `#rx-detail`，商品页、详情和 AI 页两边入口都打开 |
| 未登录点咨询会记住跳转；若登录前地址已改到处方或订单，成功后仍会被拉回咨询 | 只有地址仍停在点击咨询时的页面，登录成功才进入 `#consult`；改地址、关闭登录、退出或令牌失效都会取消这次跳转 |
| 咨询 JSON 在 401 时仍可能自动刷新令牌，和购物车、订单、处方不一致 | `request.js` 对 `/member/consultation/` 同样跳过自动刷新 |
| 咨询页只写「处方入口」、处方页没有回咨询 | 咨询页链到 `#rx-submit`，处方页链到 `#consult` |
| 处方药详情写成审核后即可购买 | 写明可提交申请并查看结果，核准后的结算与付款尚未在电脑端开放 |
| 处方单测把「咨询仍未接入」写成断言 | 改为两边都已接入，消息中心仍未接入 |
| 离线编译名单没有处方页 | 补上 `PrescriptionPages.vue` |

会员注册、登录、找回密码、资料、找药、购物车、普通结算和订单查询沿用 `main` 已有实现，本轮没有改写这些业务规则。支付仍只展示能力探测结果；探测失败或非本机验收时明确不可用。页面不生成审核结论或客服回复。

## 验证

在 `customer-web/`：

| 命令 | 退出码 | 结果 |
| --- | --- | --- |
| `npm test` | 0 | 245 通过，0 失败，0 跳过 |

`npm ci` 在 npm 10.9.9 上因锁文件里空的可选依赖 `node_modules/rollup/node_modules/@rollup/rollup-freebsd-x64` 报 `Invalid Version`。安装时临时去掉该项后成功，随后把锁文件恢复为仓库原件，没有提交 lock 或 `package.json` 改动。

无后端时用 `vite preview`（`http://127.0.0.1:4195`）和 headless Chrome 点过：商品页同时有处方购药和咨询药师；未登录点咨询只打开登录、地址仍是 `#catalog`，关闭后也不进入咨询；「我的处方」进入登录空态，并可再进 `#consult`；消息中心说明真实支付、处方结算和药师审核未接入。桌面 1280 与手机 390 宽度下入口没有互相挡住。商品列表显示「无法连接服务」，没有合成商品、会话或审核结果。

## 未测

- 没有会员登录后的上传、提交、收发消息、加购、下单或订单刷新。本环境有 Java 21，没有 MySQL 客户端，也没有 Docker，没有启动隔离后端。
- 没有真实短信、邮件、支付或 AI。
- 没有在管理端打开接待页，也没有药师审核操作。

## 剩余阻断

1. 咨询员工权限：PR #4 在隔离空库记录，未给套餐授权时员工接口为 403；演示员工不是药师，药师档案没有绑定登录用户，药师会话无法由该员工接待。本轮不改 SQL、套餐、角色或权限。最小复现见 `CONSULTATION-EXECUTION.md` 的联调段。
2. 处方与咨询的真实 HTTP 仍未在本环境重放。无后端时电脑端停在连接失败或登录空态，不补数据。
3. 处方列表接口没有显式排序，电脑端仍按 `createTime`、`id` 倒序展示。
4. 消息中心、真实支付、处方结算和药师审核不在本轮。
